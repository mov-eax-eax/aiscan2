## 2. The complete reserved set

Reserved = HTTP 403, code 40301, "forbidden - authentication required". A name claimed
with a lock. Eight found:

    claude   home   inbox   me   private   opencode   agents   warp

All are short, generic, obvious words - exactly where a naive agent topic name lands.
That is why they matter: a claimed name does not end the search, it REDIRECTS it.


## 3. The two results worth keeping

### Reserved names are a GENERATOR, not a dead end

When the obvious name is taken, users do not fall back to something random - they
DERIVE. Measured:

    claude    RESERVED  ->  claude-code              214 messages
                            claude-notifications     110 messages
    opencode  RESERVED  ->  opencode-notifications    14 messages
    codex     occupied  ->  codex1                    89 messages
    home      RESERVED  ->  myhome                    16 messages
    me        RESERVED  ->  my-notes                   3 messages

Four of the largest agent channels recovered sit exactly one derivation step from a
name the service had already claimed. The rule is mechanical, so the candidate space is
ENUMERABLE rather than guessed. 234 candidates were generated offline
(data/derive-candidates.json); none was ever probed, because the service blocked us
first. That list is the single most valuable artifact here and it is untouched.

### The harness namespace, and what is NOT there

Harness names yield; vendor names do not. Measured across 36 vendor names: two reserved
(warp, claude), one occupied (kiro, 1 message), thirty-three free. The harness EVENT
vocabulary is completely empty - 13 of 13 free (agent-done, needs-input, approval,
permission-request, task-complete, turn-complete, session-complete, agent-events,
agent-status, notifier, ai-notifier, ai-notifications).

Combined with the installers' behaviour (128 random bits generated by default, topic
described as "the password"), the exposed population is the ERROR RATE of a
privacy-correct default. The mass sits in the names HUMANS TYPE, not the names vendors
ship. Vendor-name probing is measured as low yield; do not repeat it.

## 5. Method that worked

    LOCAL ANALYSIS IS FREE. NETWORK IS RATIONED.
      structure.js, voice-rank.js, derive-candidates.js and archive-manifest.js all run
      offline over data/. Every one of them produced a real result at zero network cost.

    VERIFY THE SUBJECT BEFORE ANALYSING IT.
      A message believed to be from "test" was actually from "alerts".

    AN HTTP STATUS IS NOT AN ERROR CLASS.
      Parse the body. 40301 is permanent (isolate the name); 429xx is transient (wait).
      Conflating them produced an infinite retry loop and a false published conclusion.

    ALWAYS READ THE BODY, including on non-200. The diagnosis is in the JSON.

    A REST THAT DOES NOT CHANGE THE OUTCOME IS NOT A REST.
      If the same failure reproduces after a longer wait, the cause is permanent and
      waiting IS the bug.

    PREFER AN EXPLICITLY LABELLED IDENTIFIER.
      UUIDv7 ids gave per-turn agent think-time at no content cost - but only after
      switching from an unlabelled max() to the ids payloads label "Turn:".

    CHECKPOINT ATOMICALLY. A throttle rejects an ENTIRE multi-topic request, so one
      unknown name discarded every readable result in its batch.


## 6. Why we stopped

Not only the block. The block was self-inflicted:

  1. Sustained 429s were the warning. We received 257 rate-limited responses.
  2. The reserved-name bisect then made ~40 rapid requests, and the prober cycled
     through repeated throttle-retry.
  3. At ~19:25 the API host began dropping our TCP connections entirely - a firewall
     DROP, not an HTTP status, which is why the prober reported status 0 and no error
     branch recognised it.
  4. Four checks separated host from network: DNS resolved, TCP 443 refused, a control
     host returned 200, and an independent multi-region probe service reported ntfy.sh
     UP at 11 ms with zero outage reports. The service was healthy; we were refused.

The honest conclusion is that we were consuming a shared public resource past the point
it was telling us to stop. Polling an unknown name also CREATES it; this project created
roughly 150 topics as a side effect of looking, which is a smaller version of the exact
category error it documents.

DECISION: ntfy.sh is not contacted again. The tooling stays as a record of method.


## 7. Ethics

Read-only throughout. No message was ever published to any topic we did not create, no
agent or person was ever contacted, no credential and no seed was ever used.

A 12-word BIP39 mnemonic was found on a public topic. It is treated as a live wallet
seed: it is NOT reproduced here, it was never used, and it was never transmitted. There
is no non-invasive disclosure channel available for it, and that absence is itself a
finding rather than an obstacle.

Personal identifiers observed in the corpus are aggregated, not reproduced, beyond the
minimum needed to evidence the failure.
